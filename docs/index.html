Scheduler for Java

A small Java scheduler for immediate execution, delayed jobs, repeating tasks, listeners, logging, and service-style workers.

View examples Browse API
Single or multi-executor scheduling with optional virtual threads

What it does

Runs tasks immediately, after a delay, or on an interval, while keeping execution predictable and easy to inspect.

Quick links

  • View examples
  • Browse API

Highlights

Priorities, listeners, JSON debugging, optional virtual threads, and a `Service` abstraction for recurring jobs.

Getting started

The library is designed to stay small and direct. Create a scheduler, start it, then schedule work using the overload that best fits your task.

01

Create the scheduler

Use `new Scheduler(...)` with a name, executor count, log size, or optional virtual thread support depending on your use case.

02

Start execution

Call `start()` before scheduling tasks so the executor threads begin processing the queue.

03

Schedule work

Use `execute(...)`, `schedule(...)`, `scheduleAtInterval(...)`, or `createUnscheduledTask(...)` depending on whether you want immediate or deferred control.

Usage examples

All examples from the README, formatted as clean Java code blocks.

Create Scheduler

Create Scheduler
Java
public static void main(String[] args) {

        Scheduler scheduler = new Scheduler("Example"); 
        scheduler.setLogSize(5);
        scheduler.start();

        scheduler.execute(() -> {
            System.out.println("Immediate");
        });

        scheduler.schedule(() -> {
            System.out.println("Delayed");
        }, 2000);

        scheduler.scheduleAtInterval(() -> {
            System.out.println("Repeating");
        }, 1000);

        String result = scheduler.schedule(() -> {
            return "Callable result";
        }, 1000);

        System.out.println(result);
    }

Tasks

Tasks

Service abstraction

The README also includes service-specific examples, reproduced below in the same simple style.

Creating a Service

Creating a Service
Java
public class MyService extends Service<String> {

    public MyService() {
        super("MyService", 1000);
    }

    @Override
    protected void startup() {
        System.out.println("Service started");
    }

    @Override
    protected void execute() {
        System.out.println("Running task");
    }
}
// Start Service
MyService service = new MyService();
service.start();

// Stop Service
service.shutdown();

// Interval Control
service.setInterval(2000);

Service Listeners

Implementation note

In the current source, the `Service` constructor schedules `startup()` after a short delay before the recurring main task begins. If you build on top of it, that timing is worth keeping in mind when you expect immediate initialization.

Startup is scheduled automatically

API reference

This section documents the public surface of the main classes in the repository. It includes the methods exposed by `Scheduler`, `Task`, `Service`, and the listener/helper interfaces.

`Scheduler`

Core scheduler entry point used to create, queue, execute, inspect, and manage tasks.

  • `start()`
  • `execute(...)` overloads for `Runnable`, `Callable`, and `TaskRunnable`
  • `schedule(...)` overloads for delayed work
  • `scheduleAtInterval(...)` overloads for repeating work
  • `createUnscheduledTask(...)` overloads for deferred scheduling
  • `cancelTask(Task)`
  • `shutdown()`
  • `onShutdown(Runnable)`
  • `setLogSize(int)`, `getLogSize()`
  • `setShutdownOnCompleteAllTasks(boolean)`, `isShutdownOnCompleteAllTasks()`
  • `addTaskListener(TaskListener)`, `removeTaskListener(TaskListener)`, `getTaskListenersCopy()`
  • `getCopyTasks()`, `getTasksSize()`, `getIntervalTasksSize()`, `getNotIntervalTasksSize()`
  • `toJson()`, `toJsonThreadInfo()`
  • `getSchedulerByCurrentThread()`, `getSchedulerByThread(Thread)`
  • `isSingleThread()`, `isMultiThread()`, `isVirtualThread()`, `isShutdown()`
  • `getExecutors()`, `getExecutor(Task)`, `isThreadExecutor(Thread)`, `isCurrentThreadExecutor()`
  • `getName()`, `setName(String)`, `getExecutorName(int)`
  • `hasTasks()`, `hasTasksOnInterval()`, `tryShutdownWhenAllTasksCompleted()`

`Task`

Represents a scheduled unit of work with timing, state, result tracking, and lifecycle hooks.

  • `execute()`
  • `schedule()`
  • `cancel()`
  • `get()` and timed overloads
  • `getSkippingInterrupted()`
  • `onFinally(Runnable)`
  • `onCatch(TaskException)`
  • `getDelay()`, `setDelay(long)`, `getDelayInMillis()`
  • `getInterval()`, `setInterval(long)`
  • `getStart()`
  • `getExecutions()`
  • `getName()`, `setName(String)`
  • `getPriority()`
  • `getId()`
  • `getExecutionTime()`
  • `getError()`
  • `isCompleted()`, `isCanceled()`, `isInterval()`, `isInExcution()`
  • `getDelaySystemTime()` and the overload that accepts a start time
  • `toJson()` and `toString()`

`Service`

Abstract scheduled service layer for recurring background jobs.

  • Constructors with `name`, `interval`, and optional virtual thread support
  • Abstract hooks: `startup()` and `execute()`
  • `shutdown()`
  • `setInterval(long)` and `getInterval()`
  • `forceExecute()`
  • `forceExecute(long)`
  • `forceExecuteAsync()`
  • `getMainTask()`
  • `getListeners()`
  • Protected hooks: `beforeExecute()`, `afterExecute()`, `executeValue(T)`

Listener and helper interfaces

These interfaces are used to react to task and service lifecycle events.

  • `TaskListener`: `onTaskStarted`, `onTaskCompleted`, `onTaskCanceled`, `onTaskAdded`
  • `TaskRunnable`: `run(Task task)`
  • `TaskException`: `run(Exception exception)`
  • `ServiceListener`: `beforeExecute`, `afterExecute`, `executeValue(T value)`

Architecture notes

The implementation is intentionally simple to keep task ordering predictable while still allowing multiple executor threads when requested.

Task queueing

Tasks are stored, ordered, and dispatched based on delay, interval timing, and priority.

Executor management

Executors process tasks sequentially, which keeps execution predictable and makes it easier to reason about background work.

Observability

Listeners, logging, and JSON serialization provide visibility into scheduler state during development and debugging.
